DECISIONES

Base ya definida

Una sola fuente de verdaddocs/planning/panel-control.html decide el backlog de producto y seguridad. Aquí solo se registra la capacidad operativa de los agentes.
Separación de responsabilidadesEl orquestador coordina; backend, frontend y QA trabajan con permisos y archivos acotados. Ningún agente se autoaprueba.
Estado verificable, no aspiracional“Completado” exige evidencia en el repositorio. Credenciales, migraciones remotas, merges y despliegues permanecen pendientes hasta validación humana.
Definition of Done obligatoriaCada tarea termina con alcance cumplido, diff revisado, validaciones pertinentes, evidencia y documentación sincronizada; sin código muerto ni secretos.
Skills propias y auditadasSkillsMP aporta referencias, no instalaciones. Cada patrón útil se reescribe, reduce, prueba y versiona como skill interna.
Jev sigue siendo un pilotoNo genera código ni toma decisiones irreversibles. Requiere benchmark, feature flag, trazabilidad, umbral de confianza y fallback humano.

Cómo reutilizar este HTML en otro proyecto

Estructura: replica el formato (fases con tareas de estados pendiente/en curso/completado/bloqueado, guardarraíles, bitácora verificable, notas guardadas en el navegador) pero con el contenido de ESTE proyecto: [nombre del proyecto, objetivo, stack, reglas innegociables]. 2. La columna «estado» describe las decisiones del CRM RAI Agency; NO las copies: reevalúa cada efecto y práctica con las reglas de este proyecto (por ejemplo, si aquí sí se permite el desenfoque). 3. Propón qué efectos, prácticas y tecnologías adoptar, cuáles descartar y por qué, antes de implementarlos. Marca el costo de rendimiento y la accesibilidad de cada uno. 4. Mantén el principio de fuente única de verdad y evidencia verificable: nada se marca «completado» sin prueba (código, pruebas, build o captura). 5. GUARDRAILS

Intervenciones y límites obligatorios

Identidad, secretos y permisos

Login, 2FA, tokens, variables de entorno y ampliaciones de acceso siempre quedan en manos humanas; nunca se copian al roadmap.

Datos y migraciones

RLS, datos reales, restauraciones y prisma migrate deploy remoto requieren respaldo, revisión y aprobación explícita.

Git

Ningún agente hace push, merge, borrado, reversión o reescritura de historial sin confirmación. QA no aprueba su propio cambio.

Vercel

Preview antes de producción; variables, logs, build, smoke tests y rollback deben verificarse antes de autorizar el despliegue.

Operación nocturna

Cola finita, sesión activa, equipo sin suspensión, límites de tiempo, checkpoints y parada ante error, ambigüedad o cambio de alcance.

Definition of Done global

Alcance cumplido, diff limpio, validaciones verdes, evidencia, documentación sincronizada y cero secretos, imports sin usar o componentes muertos.
